# Malformed reference files

Deliberately **non-conforming** OSF files. They exist so that every
implementation can demonstrate — rather than assume — that it handles the
anomaly uniformly.

These files are not examples of valid OSF. Do not copy them as templates, and
do not use them as fixtures for anything other than the anomaly they encode.

**Why a separate directory:** the low-level directory-scanning harnesses (Rust,
C++, Java) that glob `examples/generated/*.osf` **non-recursively** never see
files in here — that is what the sub-directory buys, the same arrangement
`integrity/` uses.

That is *not* the whole story, though, and it is important not to read it as
"opt-in". Each file here is also a **key in `examples/reference_manifest.json`**
(see "Manifest participation" below), and four conformance tests —
`conformance_manifest_test.rs`, `test_conformance_manifest.cpp`,
`ConformanceManifestTest.java`, and Delphi's `ConformsToReferenceManifest` —
iterate *every* manifest key with no opt-in at all. So the directory keeps
these files out of the glob-based harnesses, but the manifest reaches them
explicitly, and every manifest-driven conformance test loads and asserts
against them automatically. (The same is true of `integrity/`: its four files
are manifest keys too, not an opt-in precedent in their own right.) Adding a
file here and a matching key in the manifest is therefore what forces every
implementation's reader to face the anomaly: there is no per-suite
registration step, so a corpus file cannot land in only some of the four
conformance suites — each reader either handles the anomaly correctly or its
own suite fails (tracked under OSF-UP3).

## `osf5_zero_length_block.osf`

One timestamped `double` channel (`Sensor/Double`) with ten readable samples
and one **zero-length data block** sitting between the fifth and the sixth
sample. The bad frame is channel index `0` followed by a length field of `0`,
and nothing else — no control byte.

**Expected reader behaviour** (spec: `docs/{en,de}/osf_general.md` §*Zero-length
data blocks*; DECISIONS §25): skip the frame, count one zero-length skip,
continue scanning, and deliver all ten samples.

**Manifest participation.** Listed in `examples/reference_manifest.json` under
the sub-path key `malformed/osf5_zero_length_block.osf`, with an `anomalies`
field: `{"zeroLengthBlocks": 1}`. `anomalies` is optional, mirroring how the
existing optional `integrity` field works — a file that omits it is asserted
to be well-formed (zero of every anomaly kind); a file that carries it must
report *exactly* the stated count for each kind. Every manifest-driven
conformance test (Rust, C++, Java, Delphi) loads this file like any other
manifest entry and checks both the channel data and the `zeroLengthBlocks`
count.

**Rule for the next anomaly kind:** every anomaly kind added to this scheme
must have at least one corpus file declaring a *nonzero* count for it. An
anomaly kind that only ever appears as `0` across the whole manifest is
asserted vacuously in all five implementations' conformance tests — it proves
nothing, because every reader trivially reports zero for a counter it never
increments.

**Provenance.** This is a *minimal synthetic reproduction*. Blocks of this shape
were observed in real field recordings in July 2026; those recordings are
full-size and not redistributable, so the corpus carries a handcrafted minimum
instead. **The writer that produces them has not yet been identified** — the
five reference writers in this repository are audited separately (OSF-UP3
writer negative proof). When the producing writer is found, record device,
firmware and writer version here.

Generated by `cargo run --example gen_malformed_refs` from
`implementations/rust/osf-core/`. Note: the writer stamps `created_utc` at
write time, so re-running the generator updates only that timestamp's digits;
the channel data and the anomaly are deterministic.
