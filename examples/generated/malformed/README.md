# Malformed reference files

Deliberately **non-conforming** OSF files. They exist so that every
implementation can demonstrate — rather than assume — that it handles the
anomaly uniformly.

These files are not examples of valid OSF. Do not copy them as templates, and
do not use them as fixtures for anything other than the anomaly they encode.

The low-level test harnesses glob `examples/generated/*.osf` non-recursively,
so files in this sub-directory are only ever read by tests that opt into them —
the same arrangement `integrity/` uses.

## `osf5_zero_length_block.osf`

One timestamped `double` channel (`Sensor/Double`) with ten readable samples
and one **zero-length data block** sitting between the fifth and the sixth
sample. The bad frame is channel index `0` followed by a length field of `0`,
and nothing else — no control byte.

**Expected reader behaviour** (spec: `docs/{en,de}/osf_general.md` §*Zero-length
data blocks*; DECISIONS §25): skip the frame, count one zero-length skip,
continue scanning, and deliver all ten samples.

**Provenance.** This is a *minimal synthetic reproduction*. Blocks of this shape
were observed in real field recordings in July 2026; those recordings are
full-size and not redistributable, so the corpus carries a handcrafted minimum
instead. **The writer that produces them has not yet been identified** — the
five reference writers in this repository are audited separately (OSF-UP3
writer negative proof). When the producing writer is found, record device,
firmware and writer version here.

Generated by `cargo run --example gen_malformed_refs` from
`implementations/rust/osf-core/`.
